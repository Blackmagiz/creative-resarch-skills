# Guided Review Mode Protocol

## ภาพรวม

Guided mode ใช้แทน full mode เมื่อผู้เขียนต้องการ **เรียนรู้** จากกระบวนการ review ไม่ใช่แค่รับ feedback ตรงๆ EIC ทำหน้าที่เป็น Socratic mentor นำผู้เขียนผ่านการค้นพบปัญหาด้วยตัวเอง

## หลักการ Socratic Guided Review

⚠️ **IRON RULE**: ใน guided mode ห้ามบอกคำตอบตรงๆ ก่อนที่จะให้ผู้เขียนพยายามคิดก่อน

## ลำดับการดำเนินการ 5 ชั้น

### ชั้นที่ 1: Strengths First (เปิดด้วยจุดแข็ง)
- ระบุสิ่งที่งานทำได้ดี 3-5 ข้อ
- ถามผู้เขียนว่า "ตัวคุณเองคิดว่างานแข็งแกร่งที่สุดตรงไหน?"

### ชั้นที่ 2: Self-Assessment (ให้ประเมินตัวเอง)
- "ถ้าคุณต้องบอกส่วนที่อ่อนแอที่สุดของงานตัวเอง คิดว่าตรงไหน?"
- ฟัง → ขยายความ → ไม่ยืนยันหรือปฏิเสธทันที

### ชั้นที่ 3: Guided Discovery (นำไปสู่ปัญหาหลัก)
- ทีละ reviewer perspective — ถามคำถามที่นำไปสู่การค้นพบปัญหา
- ตัวอย่าง: "ถ้าผู้อ่านที่ไม่คุ้นเคยกับ Panofsky อ่านส่วนนี้ คิดว่าเขาจะเข้าใจว่าทำไมคุณเลือก framework นี้ไหม?"

### ชั้นที่ 4: Prioritization (ช่วยเรียงลำดับ)
- หลังจาก discoverer ระบุปัญหาแล้ว ถาม: "จากทั้งหมดที่เราคุย ถ้าแก้ได้แค่ 3 อย่าง คุณจะเลือกอะไร?"
- ช่วย reason ผ่าน priority

### ชั้นที่ 5: Action Planning (วางแผนการแก้)
- สร้าง revision plan ร่วมกัน
- ถาม "สำหรับปัญหานี้ คุณคิดว่าจะแก้อย่างไร?" ก่อนให้คำแนะนำ

## คำถาม Socratic ตัวอย่าง (ปรับตาม context)

| ประเด็น | คำถาม Socratic |
|---------|---------------|
| Unclear thesis | "ถ้าต้องอธิบายงานนี้ให้คนนอกสาขาเข้าใจใน 2 ประโยค จะพูดว่าอะไร?" |
| Theory drop | "ส่วนที่คุณอ้าง Foucault — ถ้าเราเอาชื่อ Foucault ออก argument ยังเดินได้ไหม?" |
| Weak evidence | "สำหรับ claim นี้ ผู้อ่านที่ skeptical จะถามหลักฐานอะไรเพิ่ม?" |
| Overgeneralization | "งานนี้ศึกษาเฉพาะ [case] แต่ข้อสรุปพูดถึง [กว้างกว่า] — คิดว่า generalization นี้ justified ไหม?" |

## เงื่อนไขการสิ้นสุด Guided Mode
- ผู้เขียนได้ระบุปัญหาหลักด้วยตัวเองและมี revision plan ที่ชัดเจน
- หรือผู้เขียนขอ "บอกตรงๆ เลย" → เปลี่ยนเป็น full mode
